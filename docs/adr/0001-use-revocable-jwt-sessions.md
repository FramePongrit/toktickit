# Use revocable JWT sessions

Lab 3 authentication uses a signed JWT stored in an HttpOnly cookie, with each token tied to an `AuthSession` record that is checked on every protected request. This keeps JWT-based authentication while allowing immediate logout revocation and ensuring account activation, role, and mandatory-password-change rules always use current database state; purely stateless JWTs were rejected because they leave authorization claims valid until expiry. A user may have multiple active sessions: normal logout revokes only the current session, while password change, administrator password reset, or account deactivation revokes every session for that user. A successful password change creates a fresh session for the current device. Each session has a fixed eight-hour lifetime with matching JWT and database expirations; there is no sliding renewal, refresh token, or remember-me option in Lab 3. Because browsers send the authentication cookie automatically, every state-changing authenticated request must also carry a session-bound CSRF token; the cookie uses HttpOnly and SameSite=Lax, adds Secure outside local development, and the server accepts credentialed requests only from the configured client origin.
